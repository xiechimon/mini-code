# Spec: 终端体验打磨（行式 REPL）

Status: ready-for-agent

## Problem Statement

作为 mini-code 的终端用户，每次 agent 干活时屏幕上倾倒原始 JSON 参数和最多 800 字符的工具结果，结论被淹没；所有行一个样式，工具、结果、错误无法扫读区分；输入区只有裸提示符——提问历史重启即失、多行需求难以输入；启动时 4 行横幅占满屏头；每轮结束还有一行「完成（共 N 条消息）」的噪音。

## Solution

在行式 REPL 内做一次体验打磨（不引入全屏 TUI、不做流式）：

- 工具调用渲染为「一行摘要 + 结果首行 + 多行折叠」，失败才展开红色全文
- 四色角色配色（工具名青 / 参数暗灰 / 成功绿 / 失败红 / 横幅粗体），颜色只标角色
- 输入编辑器增强：历史跨会话持久化、❯ 提示符、反斜杠续行与多行粘贴
- 启动横幅压成一行；轮末统计压成一行耗时
- `NO_COLOR` / 非 tty / `TERM=dumb` 标准降级，管道输出干净文本

## User Stories

1. 作为终端用户，我希望工具调用显示为一行摘要（工具名 + 关键参数），以便不翻原始 JSON 就知道 agent 在做什么
2. 作为终端用户，我希望工具结果默认只显示首行，以便快速看到关键输出
3. 作为终端用户，我希望多行结果被折叠为「… 共 N 行」，以便结论不被刷屏淹没
4. 作为终端用户，我希望工具失败时看到完整错误信息且为红色，以便定位问题
5. 作为终端用户，我希望工具名、参数、成功结果、失败结果使用不同颜色，以便扫读层级
6. 作为终端用户，我希望颜色只用于角色区分而不用于装饰，以便视觉安静
7. 作为终端用户，我希望每轮结束看到一行「N 轮 · M 次工具 · 耗时」，以便了解本轮开销
8. 作为终端用户，我希望启动横幅只有一行，以便快速进入工作状态
9. 作为终端用户，我希望横幅里看到 provider/model 与工作目录，以便确认环境
10. 作为终端用户，我希望提示符是醒目的 ❯，以便一眼找到输入位置
11. 作为终端用户，我希望提问历史跨会话持久化，以便重启后 ↑ 仍能翻到上次的输入
12. 作为终端用户，我希望粘贴多行文本时整体进入缓冲、一次提交，以便输入结构化需求
13. 作为终端用户，我希望用行尾反斜杠手写续行，以便手动输入多行需求
14. 作为终端用户，我希望 Ctrl-C 只放弃当前行而不退出程序，以便重新输入
15. 作为终端用户，我希望 Ctrl-D 干净退出，以便按惯例结束会话
16. 作为管道/脚本使用者，我希望非 tty 环境下输出不含 ANSI 码，以便 grep 与日志干净
17. 作为管道/脚本使用者，我希望设置 NO_COLOR 后即使在 tty 中也无色输出，以便遵循通用约定
18. 作为管道/脚本使用者，我希望 TERM=dumb 下去色，以便在最小终端中正常使用
19. 作为维护者，我希望事件渲染是纯函数（不读环境、不碰时钟），以便不启动终端即可单测
20. 作为维护者，我希望新增渲染行为都有单测护栏（摘要规则、折叠规则、去色开关），以便防止回归
21. 作为维护者，我希望事件渲染独立于 AgentLoop 协议，以便 MVP3 流式接入时复用同一渲染层
22. 作为维护者，我希望本轮零新增第三方依赖（只用 JLine 已有能力与手写 ANSI），以便依赖面不膨胀
23. 作为维护者，我希望轮次耗时由调用方测好后传入渲染器，以便渲染器保持确定性可测

## Implementation Decisions

- 新增渲染器模块于 cli 层，收敛全部事件渲染：输入为 agent 事件与样式对象，输出为文本；入口类只做组装
- 样式开关由 `detect(环境变量, 是否 tty)` 决定：`NO_COLOR` 非空、非 tty、`TERM=dumb` 任一命中即去色；渲染器其余部分不读环境
- 配色（暗色友好四色）：工具名 cyan、参数与辅助信息暗灰、成功结果绿、失败结果红、横幅名称粗体；成功/失败色也用于轮末统计的对应部分
- 工具参数摘要规则：read/write/edit 取 path；bash 取 command（截 60 字符）；其他工具取紧凑 JSON（截 60 字符）
- 工具结果渲染规则：成功显示首行；多行追加「… 共 N 行」；失败显示全文（封顶 500 字符）并以失败色标记
- 轮末统计行：「N 轮 · M 次工具 · X.Xs」；耗时由调用方计时后传入，工具次数由事件流累计
- 启动横幅一行：`mini-code · provider/model · 工作目录`；无 API Key 警告继续走 stderr
- 输入编辑器：JLine FileHistory 持久化（路径可注入，默认 `~/.mini-code/history`）；提示符 ❯；行尾反斜杠续行；JLine 括号粘贴天然支持多行进缓冲；Ctrl-C 弃行、Ctrl-D 退出语义保持
- 管道模式与交互模式使用同一渲染器（去色后输出），保证两种模式文案一致
- 术语遵循 CONTEXT.md：输入编辑器 / 事件渲染 / 等待反馈 三分面；本规格只动前两面
- 事件渲染保持独立于 AgentLoop 协议层，AgentEvent 契约不变

## Testing Decisions

- 单缝原则：全部渲染断言收敛在渲染器纯函数缝上——给定事件序列与样式开关，断言输出字符串（含 ANSI 与去色两种模式都覆盖）
- 只测外部行为：不断言内部方法调用；摘要规则、折叠规则、颜色角色、降级开关都通过输出文本观察
- 输入编辑器走现有 `runJLineRepl(Terminal, ...)` 缝（ExternalTerminal dumb 模式），不立新缝；历史持久化用 JUnit `@TempDir` 注入路径验证落盘
- 先例：MainReplTest（cli 层输入测试）、ReadToolTest（@TempDir 注入）、AgentLoopTest（假 LlmClient 驱动事件流）
- 完成标准：`mvn test` 全绿；另以 pty 实测（expect 脚本）人工验收视觉效果

## Out of Scope

- 流式 SSE 与等待动画（等待反馈面，归 MVP3）
- 光标行语法高亮（括号配对着色）
- slash 命令（/clear、/history 等）
- 全屏 TUI（MVP4，对齐 pi-tui）
- 回复正文的 Markdown 渲染
- AgentEvent / AgentLoop 协议层改动
