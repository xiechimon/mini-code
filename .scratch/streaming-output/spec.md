# Spec: 流式输出（等待反馈面落地）

Status: ready-for-agent

## Problem Statement

按下回车后终端只剩一行「思考中」，长回复要等 30–60 秒才一次性倾倒；生成走偏了无法取消，只能干等；更糟的是生成期间按 Ctrl-C 会直接杀掉整个 REPL 进程，丢掉整段会话。等待过程是一个黑盒，用户对「正在生成什么、生成了多少、要不要等」完全没有掌控。

## Solution

助手回复逐字流式上屏：模型每吐一段文本，终端立刻显示；回复完成后自动替换为 Markdown 渲染版（表格/代码盒/标题）。生成期间 Ctrl-C 优雅取消——已生成的半截内容保留并标记「⏹ 已中断」，对话可继续，进程不退出。工具调用仍按既有摘要渲染（不流式）；管道模式保持非流式行为。SSE 不可用时自动回退一次非流式，保证回复一定能拿到。

## User Stories

1. 作为终端用户，我希望助手回复逐字上屏，以便立刻看到回复方向而不对着「思考中」干等
2. 作为终端用户，我希望回复流式完成后自动替换为渲染后的 Markdown 版本，以便流式的即时性与渲染的可读性兼得
3. 作为终端用户，我希望流式期间按 Ctrl-C 取消生成而进程不退出，以便随时叫停走偏的回答
4. 作为终端用户，我希望中断后已生成的半截回复保留在屏幕上并标记「⏹ 已中断」，以便保留已生成的信息
5. 作为终端用户，我希望中断后继续提问时上下文完整，以便对话不被中断打断
6. 作为终端用户，我希望中断时未执行的工具调用不再执行，以便不产生多余的副作用
7. 作为终端用户，我希望首个字符到达后「思考中」占位行被实际内容替换，以便屏幕上不残留占位信息
8. 作为终端用户，我希望工具调用仍以单行摘要呈现，以便工具活动与正文在视觉上可区分
9. 作为终端用户，我希望模型不支持流式或网络异常时自动回退非流式，以便回复永远能拿到
10. 作为终端用户，我希望非流式回退时的输出与既有体验一致，以便降级无感
11. 作为终端用户，我希望多轮对话中流式与中断可以反复使用，以便长会话中随时掌控
12. 作为管道/脚本使用者，我希望管道模式下输出保持非流式整体返回，以便重定向与解析行为可预期
13. 作为管道/脚本使用者，我希望管道模式输出不含流式光标控制序列，以便日志干净
14. 作为维护者，我希望 SSE 行解析是纯函数（行序列→事件），以便不联网即可穷举协议形态
15. 作为维护者，我希望 HTTP 传输层极薄（字节流喂给解析器），以便网络逻辑与协议逻辑分离
16. 作为维护者，我希望有本地 fake SSE 服务的集成测试，以便端到端验证字节→事件→partial
17. 作为维护者，我希望测试用 fake LlmClient 零改动即可工作（接口向后兼容），以便既有测试不回归
18. 作为维护者，我希望中断触发器可注入，以便 OS 信号不可测性不影响 abort 语义的单测
19. 作为维护者，我希望协议扩展（新增流式事件）在规格中显式记录，以便理解为何推翻「协议层不动」的旧约束
20. 作为维护者，我希望流式失败回退非流式有日志可查，以便排查网关兼容性问题
21. 作为维护者，我希望实现首个任务用真实网关做流式 spike，以便确认各模型 stream 行为一致
22. 作为维护者，我希望既有 Markdown 渲染/四色/表格/宽度注入能力零回归，以便流式是增量而非重写
23. 作为终端用户，我希望流式期间的 Ctrl-C 在流式结束后恢复「弃输入行」原语义，以便按键行为可预期
24. 作为维护者，我希望中断后的 partial 以 aborted 终态进入对话历史，以便后续轮次的上下文拼接正确

## Implementation Decisions

- LlmClient 接口以 default 方法扩展流式能力：新增 stream 签名（模型、上下文、片段回调 → 最终 Message），默认实现委派既有同步方法且回调零次；OpenAiCompatClient 覆写为真流式。既有同步方法保留，作为回退路径与 fake 测试的基础
- OpenAiCompatClient 流式实现：请求体加 stream 标记；HTTP 用异步客户端 + 输入流响应体（可取消），逐行喂给 SSE 解析器；连接建立失败或解析异常时回退一次同步非流式调用并记日志
- SSE 解析器为纯函数：输入 SSE 文本行序列，输出解析事件（文本增量、完成、工具调用增量、可忽略行）。遵循 OpenAI chat-completions 流协议：文本增量来自 choices 的 delta 内容；工具调用以增量分片到达，客户端负责累积拼装 id/名称/参数，但不向 UI 发流式事件（工具调用不流式上屏）；`data: [DONE]` 终止；注释行与空行忽略；非 JSON 行容错跳过
- AgentEvent 协议新增流式增量事件（携带 delta 文本片段）——显式推翻此前规格「协议层不动」的约束，本规格即为该决策的记录；MessageEnd 语义不变（携带最终完整 Message）
- AgentLoop 改为消费流式接口：每个片段回调触发流式增量事件发射；片段累积为完整文本，结束后走既有 MessageEnd 路径；工具调用分发的完整 JSON 仍从拼装结果取
- 生成中断：引入可注入的中断触发器抽象（置位即取消）；CLI 在流式期间注册 SIGINT 处理器（JDK Signal API，事实标准但非规范 API——理由：无便携替代且为终端 CLI 事实做法）映射 Ctrl-C；触发后取消 HTTP 请求，AgentLoop 捕获取消并以 aborted 终态收场；流式结束注销处理器，Ctrl-C 恢复 JVM 默认/JLine 原语义
- 中断语义：已收到的文本累积为 partial 助手消息，stopReason 置 aborted 进入对话历史；渲染层对 aborted 终态追加「⏹ 已中断」标记；当轮尚未执行的工具调用不执行，循环直接结束本轮
- 回退重绘：渲染层对助手流式输出做宽度感知的行数记账；MessageEnd 渲染时先输出光标上移+清除到底部的控制序列，再输出 MarkdownRenderer 渲染结果；首个流式片段到达时同样回退覆盖「思考中」占位行
- 设计转向记录：上述回退重绘在实现验证中被线式终端硬约束推翻——滚出视口的内容进入回滚缓冲区不可擦除，超长回复用 CUU+ESC[J 必然残留双份（已用终端模拟器回路证实）。改为块级流式：模型增量累积进 markdown 块，未完成块以可原位擦除的单行进度指示（▌ n 字）呈现，块完成（空行分界/围栏闭合）即打印该块的渲染版，一次成型永不重绘。纯函数缝纪律不变（MarkdownRenderer 只做块渲染），有状态的只是块边界检测与进度输出
- 管道模式（非 tty）不启用流式与重绘：走既有同步路径，输出无光标控制序列
- 术语遵循 CONTEXT.md：等待反馈 / 流式增量 / 生成中断 / 正文渲染 / 纯函数渲染缝

## Testing Decisions

- 单缝原则：SSE 行解析器是唯一新增纯函数缝——给定行序列断言事件输出，覆盖：文本增量分片、完成标记、工具调用增量（解析但标记为不外发）、注释行/空行忽略、非 JSON 行容错、跨块 data 拼接
- HTTP 集成一条：JDK 内置 HttpServer 起本地 fake SSE 服务（分块+可控制延迟），端到端验证字节流→事件→partial 累积；另验证取消：服务端慢速发送时触发取消，客户端及时返回且返回已收到部分
- AgentLoop 缝复用：fake LlmClient 实现流式回调（零改动既有 fake），断言事件序列（增量×N→MessageEnd）；注入中断触发器，断言 partial+aborted+工具不执行；先例 AgentLoopTest
- EventRenderer 缝复用：流式增量直出与行数记账、MessageEnd 重绘控制序列、aborted 标记，全部以输出字符串断言；先例 EventRendererTest
- pty 实测：真实网关流式回复逐字上屏 + 生成中 Ctrl-C 中断不退进程 + 中断后继续对话
- 完成标准：mvn test 全绿 + 真实网关 spike 记录 + pty 冒烟

## Out of Scope

- 工具调用的流式上屏（参数 delta 拼接实时展示）
- Esc 键中断（仅 Ctrl-C）
- 增量 Markdown 渲染（流式期间渲染半截结构）
- thinking/reasoning 内容的流式展示
- RPC/JSON 输出模式的流式
- 会话持久化与压缩（MVP3 另一半，另立规格）
- 并发多请求的分别取消
