# Spec: True Line-Level Streaming Render（取代块级流式计数器）

Status: resolved

## Problem Statement

流式期间终端上只有一个原位刷新的进度计数器「▌ 已生成 N 字」，正文被整个藏进块缓冲，直到块完成（空行分界或围栏闭合）才一次性倾销整块渲染版。用户看不到回复在流动——面对的是「计数器 + 突然一整墙文字」，对「正在生成什么、走了多远」没有实时掌控。这是上一版为绕开「滚出视口内容不可擦除」这一线式终端硬约束而做的**治标**工作──它把整个回退重绘方案换成了块级计数器，代价是彻底放弃了逐字上屏的可读性。

## Solution

生成期间，助手回复的**普通段落与标题等文本块逐行生长上屏**：文字到达即渲染、即显示、即随增量原地更新（无重复、无裸 markdown）；**代码围栏与表格等结构化块在闭合时整块定稿**（绘制成盒/表格），不在闭合前逐字流动。流式完成后不再二次重绘已定稿内容——已经上屏的就是定稿形态，滚出视口的内容进入回滚缓冲即是终态。中断仍保留已完成的部分并追加「⏹ 已中断」标记。

一句话：**把「计数器」换成「看得见的增长」**——开放块随增量原位重绘，已定稿块永不重绘。

## User Stories

1. 作为终端用户，我希望流式期间普通段落文字逐行可见地增长，以便实时看到回复方向而不对着计数器干等
2. 作为终端用户，我希望流式期间标题（#/##…）以实时增长的渲染行呈现，以便看到结构化层面的推进
3. 作为终端用户，我希望代码围栏在闭合前不逐字流动、闭合时整块绘制成边框盒，以便代码结构在完整时一次性呈现且不闪烁
4. 作为终端用户，我希望 GFM 表格在闭合时整块绘制为对齐表格，以便表格结构完整且排版稳定
5. 作为终端用户，我希望屏幕上的正文**始终是渲染后的 Markdown**，任何时刻都不出现裸的 `#` / `**` / \`\`\` 标记，以便可读性不被流式破坏
6. 作为终端用户，我希望慢速/超长回复也**绝不产生双份**（流式文字 + 渲染版叠加），以便终端回滚缓冲区干净
7. 作为终端用户，我希望文本块即使在屏幕内多次原位重绘也无视觉残留，以便看得到的始终是当前渲染形态
8. 作为终端用户，我希望开放块长到超过视口高度时优雅退化为「只追加、不再原位重绘」，以便不因 CUU 追不到滚出内容而打烂整屏
9. 作为终端用户，我希望生成期间按 Ctrl-C 取消而进程不退出，以便随时叫停走偏的回复（保持既有中断语义）
10. 作为终端用户，我希望中断后已生成的半截内容保留在屏幕上并追加「⏹ 已中断」标记，以便保留已生成信息
11. 作为终端用户，我希望首个流式增量到达时「思考中」占位行被实际正文覆盖，以便屏幕上不残留占位信息
12. 作为终端用户，我希望中断后继续提问时上下文完整，以便对话不被打断打断
13. 作为终端用户，我希望工具调用仍以单行摘要呈现（不流式），以便工具活动与正文在视觉上可区分
14. 作为终端用户，我希望多轮对话中本渲染可反复使用，以便长会话中每轮都实时可见
15. 作为管道/脚本使用者，我希望管道（非 tty）模式保持非流式整体返回、不含光标控制序列，以便重定向与解析可预期
16. 作为维护者，我希望 Markdown 渲染仍为纯函数缝（输入文本/样式/宽度→输出），以便单测断言只依赖输入、不读环境不碰时钟
17. 作为维护者，我希望有状态的部分（开放块缓冲、屏幕行数账、视图外 cap）完全收敛到流式渲染组件内，以便渲染缝保持纯净
18. 作为维护者，我希望用忠实终端模拟器断言外显屏幕状态（可见文本、无残留、无重复、围栏成盒），以便回归这类易碎光标逻辑
19. 作为维护者，我希望「流式中途正文可见」这一行为有回归测试钉住，以便不会退回计数器式治标
20. 作为维护者，我希望既有 Markdown 渲染（代码盒/表格/标题/粗体/颜色/宽度注入）零回归，以便本次是渲染叠加而非重写
21. 作为维护者，我希望样式/宽度/视口高度全部由调用方注入（不读环境），以便确定性可测
22. 作为维护者，我希望本设计决策（取代块级计数器）在规格中显式记录其取代理由，以便后人理解为何推翻上一版

## Implementation Decisions

- **流式渲染组件升级**：把现有 `BlockStreamer` 从「单行进度计数器」改为「开放块原位重绘 + 已定稿块不可变」的状态机。保留对外接口（`delta(String)` / `flush(aborted)` / `reset()`），仅重写内部实现，以此最小化对 `Main` 事件挂接的改动。
- **开放块原位重绘**：增量先累积进开放块缓冲，每增量用 `MarkdownRenderer.render(缓冲)` 重算本块渲染形态；重绘时输出「回列 0（`\r`）+ 光标上移本块当前行数（CUU）+ 清除到底（ED）」，再打印新的渲染形态。本块首行以上已定稿内容不在重绘范围内——**这是无双份、无残留的正确性来源**。
- **首增量覆盖占位行**：首个流式增量到达时，以 `\r + 清行（EL）` 覆盖 `TurnStart` 的「思考中」占位行（保留既有行为）。
- **块完成即定稿**：开放块满足「以空行分界结尾」或「以闭合围栏结尾」时，一次打印其最终渲染形态，标记 `已定稿`，光标归位到定稿内容之后；此后该块永不再重绘。
- **两种块模式**（对齐所选契约「代码围栏不逐字流动」）：
  - 可流式块（段落、标题、列表项、引用）：开放期逐增量原位重绘，随增长实时可见。
  - 仅定稿块（围栏代码块、缩进代码块、GFM 表格）：开放期不逐字重绘（避免大面积闪烁与滚动擦除），可显示一条可擦除的轻量指示（如「﹏ 代码块…」），闭合时整块绘制。
  - 块模式由缓冲**起始结构**判定（只看首行，保持确定性）：首行为围栏标记或以 `|` 分隔的表头 → 仅定稿块；其余 → 可流式块。不能因后续行事后重分类，否则会擦掉已上屏的正文。
- **视图外 cap**：对可流式块，若其当前渲染行数超过注入的视口高度，则停止原位重绘、改为只追加（增量文本直接 `println` 往下走），并据此维持「已滚出内容即终态」的 invariants。视口高度由调用方注入（JLine 交互取 `terminal.getHeight()`，one-shot tty 从探测终端取，缺省保守值）。
- **纯函数缝保持**：`MarkdownRenderer` 不改，仍为纯函数（输入 markdown/样式/宽度 → 输出文本）；`Style` 仍是 ANSI 常量唯一定义处；流式渲染组件只持有有状态的部分，不读环境、不碰时钟。
- **管道模式不变**：非 tty 走既有同步路径，零 StreamDelta、零光标控制序列。
- **术语遵循 CONTEXT.md**：流式增量、正文渲染、纯函数渲染缝、事件渲染、等待反馈、生成中断；新增语义「开放块 / 已定稿块 / 原位重绘 / 视图外 cap」在本规格定义，供后续 AGENTS 引用。

## Testing Decisions

- **单缝原则（主测试缝）**：`BlockStreamer` 是唯一流式渲染缝——给定 `delta`/`flush` 片段序列，断言输出经忠实终端模拟器后的**外显屏幕状态**。这是既有先例 `BlockStreamingResidueTest` 的既有缝，直接继承，不新增缝。
- **好测试只测外部行为**：断言最终屏幕与流式中途快照（正文可见、无计数器、无裸 markdown、恰一份、无残留、围栏成盒、中断标记、视图外 cap 退化为追加），不断言内部状态（`openRows`、缓冲等实现细节）。用 `TermSim`（忠实模拟 CUU/EL/ED/`\r`/宽字符）把光标控制序列解析为真实屏幕。
- **被测模块**：`dev.minicode.cli` 的流式渲染组件及其终端模拟器测试；`MarkdownRenderer` 的既有测试另行保持（本规格不改其缝）。
- **先例**：`BlockStreamingResidueTest`（TermSim + 长文 CJK 文章制品 + 断言终屏无裸 markdown/无重复/无进度残留 + 中断保留 partial + 表格行不擦正文）、`BlockStreamerTest`（已改写为「可见增长」行为）、`EventRendererMarkdownTest`（Markdown 内联/块渲染）。原型 `StreamingRedrawPrototypeTest` 已删除（光标数学已由正式终端模拟器测试覆盖）。
- **回归测试**：诊断期的「流式中途正文可见 / 后续增量追加可见、不退化计数器」断言已并入 `BlockStreamerTest`（`firstDeltaErasesPlaceholderAndShowsText` / `streamGrowsAcrossDeltasWithoutCounter`），并以 `BlockStreamingResidueTest.tableShapedLineAfterProseDoesNotEraseProse` 钉住「首行判定、表格形行不擦已上屏正文」。
- **完成标准**：`mvn test` 全绿（含新回归 + 既有 Markdown 渲染测试零回归）+ 真实网关 tty 冒烟（逐段可见增长 + 生成中 Ctrl-C 中断不退进程 + 长代码块闭合成盒）。

## Out of Scope

- 工具调用参数的流式展示（仅保持单行摘要，不流式）
- thinking / reasoning 内容的流式展示
- RPC / JSON 输出模式的流式
- Esc 键中断（仅 Ctrl-C，沿既有语义）
- 对已滚出视口内容的实时回流（视图外 cap 接受「已滚出即终态」的降级）
- 增量重排半截行内样式（如 `**bold**` 未闭合时的跨行流动）——按块定稿，不重新打开
- 会话持久化与压缩（MVP3 另一半，另立规格）
- 管道模式行为的任何改动

## Further Notes

- **取代记录**：本规格取代 `.scratch/streaming-output/spec.md`「设计转向记录」中所定的「块级流式」（其又取代了「回退重绘」）。取代理由：块级计数器为绕开「滚出视口不可擦除」的硬约束，放弃了流式的可读性；行级流式 + 块级定稿在保留渲染的前提下恢复逐字可见性，其正确性来自「开放块小、可原地重绘（且约束在视口内）+ 已定稿块从不重绘」——既得可见性，又避免双份。
- **风险与回归钳制**：原位重绘对真实终端（CUU/ED 跨折行、CJK 宽字符）仍是易碎点，与既往踩坑同族。缓解：忠实终端模拟器单测 + 视图外 cap + 仅定稿块不逐字重绘。任何改动必须保持 `BlockStreamingResidueTest` 无残留/无重复断言为绿。
- **对齐参照**：pi-coding-agent 的流式渲染（滚动区内逐行追加而非整块重绘）；本实现用「开放块原位重绘 + 定稿不可变」在本项目行式终端约束下逼近该效果。
- **前置已就绪**：宽度注入、`AnsiTextUtil` 折行/可见长度、`MarkdownRenderer`、中断 `aborted` 协议位、`Style` ANSI 常量均为既有能力。
